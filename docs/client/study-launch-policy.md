# Internal controlled-study launch policy

`single-root-v1` is an explicit internal Docker-runner setting. No CLI command, MCP argument, project configuration, or ordinary default enables it. It prepares inspected launch controls; it does not prove that a run has no hidden children. Real-binary validation remains required before eligibility.

The Go entry points are `runner.StudyLaunchSingleRootV1`, `RunOptions.StudyLaunchPolicy`, `pipeline.SuiteOptions.StudyLaunchPolicy`, and `runner.DockerLaunchDigestWithPolicy`. A study requires OpenCode 2.0.26, `CapturePrelaunchTree=true`, a supporting runner, and a valid frozen `RunOptions.ExpectLaunchDigest`. `RunSuite` sets that digest from its planned configuration. Unknown policies, unsupported runners, missing capture, or a mismatched actual launch refuse before agent start. Empty policy preserves ordinary install bytes, argv, environment and A/B identities.

One recipe renders actual configuration, argv, environment and installation ownership/modes. Its normalized form also generates the policy-specific A identity and the B execution identity. A includes fixed controls, binary/archive pin and target. B also binds the instruction digest, actual OpenCode binary digest and exact agent image ID. Image-dependent values remain outside A. Per-attempt gate tokens remain normalized in identities.

The study requires a bounded, root-owned regular `/usr/bin/env` with executable permissions for the nonroot agent. It launches `/usr/bin/env -i` directly, without a shell or inherited-environment fallback. A fixed explicit environment selects readonly HOME `/opt/hint/study/agent-home` and dedicated XDG/configuration roots, disables project configuration, model-list fetching and updates, and selects the existing model gate. Inspected nonempty `LD_*` or `DYLD_*` values refuse before the launcher starts. Inspection binds the launcher bytes to the exact image; it does not establish the launcher's implementation correctness or cover every executable influence.

Before installation, bounded ancestor metadata checks require canonical, root-owned, traversable, non-writable directory paths without links. The managed study root and binary destination must be absent; an inconclusive response refuses. No image contents are deleted. After installation, a complete bounded managed-root inventory must match the recipe's types, ownership, modes, content and empty initial state. Unexpected configuration, plugins, commands, credentials, saved permissions, links or extra files refuse before agent start. Limits are 128 inventory entries and 2 MiB per inspection archive, with a 30-second inspection context. Ancestor probes intentionally read only bounded first-entry metadata; they do not claim a complete recursive inventory.

The generated configuration denies legacy `task` and native `subagent` permissions and sets `experimental.subagent_depth=0`. The argv selects builtin `build`, starts a new standalone server/session, and keeps fixed title `hint-trial`. Explicit deny precedes permission asks, so `--auto` cannot approve that denied action. This does not prohibit plugin-host or server-API session creation. Isolation excludes unreviewed configured plugins and commands; ordinary root stdout cannot establish absence of other creation paths.

Local `hint_container.study_launch` metadata records only a prepared inspection receipt, its A/B/image bindings, bounded inventory and launcher digests, and Counter-monotonic timing. Its `binary_validation` remains `not_run`; its `eligibility` remains `requires_real_binary_validation`. The observed `/app` capture follows successful inspection and topology checks before the launch enclosure. The behavior handover requires matching receipt, planned digest, image, execution and capture timing. A missing or conflicting receipt produces UNKNOWN without BASE fallback. No receipt or raw source enters the public report schema.

Root-only behavior remains limited to the accepted terminal-tool decoder. Unknown/custom tools, unreviewed builtin namespaces, shell child launches, delegation, incomplete capture or uncertain controls require UNKNOWN/exclusion. Absence of a delegation record supplies no no-children proof. This policy enables no trusted producer, source-export adapter, calibration registry entry, or economic claim. A later finite binary check must verify actual behavior before any eligibility decision.
